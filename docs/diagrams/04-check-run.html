One Check run (condition D)

What happens after you press "Research this question". The coordinator plans and asks the analysts, code checks every number, the coordinator reviews its own draft once, then a critic objects and the team fixes what matters.

Scroll the diagram sideways to see all of it.

How to read it

  • Plan is one model call with no tools. The coordinator's own loop then asks analysts through ask_<analyst> tools and can use its own (find_company, calculate, screen, get_peers). An analyst keeps its conversation, so a follow-up continues where it left off.
  • Checker runs on every draft: the first one, the self-reviewed one, and each revision. It checks that every {calc:ID} or {fact:ID} resolves to a saved record and flags typed figures. It flags; it never throws an answer away.
  • Self-review: the coordinator gets the checker's flags and the critic's issue list and resubmits once (AGENT_SELF_REVIEW_PASSES = 1). Conditions B and C end here.
  • Critic loop (AGENT_CRITIC_ROUNDS = 3): review → if any objection is material, the coordinator routes the open ones to the analyst that wrote each claim and hands in a revision → checker → review again. It stops when nothing material is left, or after the third review; what is still open is marked unresolved and its claim qualified.
  • Report + trace: the host fills each slot with its record's value. Every model call, tool call and result is already in the trace, so the run can be reopened and rechecked offline.
