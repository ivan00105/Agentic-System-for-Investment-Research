Roles, tools and data

Who may run which tool, and where each tool gets its data. The loop enforces this table: a role that asks for a tool outside its row gets an "invalid" result instead of a run.

Scroll the diagram sideways to see all of it.

How to read it

  • Single agent (condition B) has every tool, and every one of them belongs to some role in the team, so B vs C tests specialisation, not tool access.
  • The coordinator also has an ask_<analyst> tool per analyst; those are how it dispatches work, so they are not rows here.
  • The critic gets every read-only tool plus verify_against_filing, but not screen: reviewing one report never needs a ranking.
  • Data sources fall back in a fixed order and every result says which one it used. A provider without its key is skipped and shown as "not configured" on the Setup page.
  • Not in the table: Discover's screener has no tools (it only writes the spec), and the host code runs screen and the 10-K check itself (diagram 5).
  • Planned rows follow PROJECT_GUIDE §9 Phase 6. B gets them automatically: its role has no tool list, so it sees every registered tool.
